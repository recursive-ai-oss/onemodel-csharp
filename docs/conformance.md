## Method

- **Data.** The frozen ONNX 1.22.0 `onnx/backend/test/data` directories `node`, `simple`, `pytorch-converted` and `pytorch-operator`, fetched by `tools/fetch_backend_test.py` at a pinned SHA-256 (the data is never committed). ONNX 1.23 and later no longer ship frozen node cases, so cases for operators newer than that release are not in the data; see the gaps above.
- **Run.** Each case's `model.onnx` is imported and a `Session` is created in the mode under test (`Fast` or `Exact`, one intra-op thread, default optimization level). Every `test_data_set_*` is fed in and every output compared with the recorded output.
- **Tolerance.** Floating-point outputs (float16, bfloat16, float32, float64) pass when each element satisfies `|got - want| <= 1e-7 + 1e-3 * |want|` or both are NaN or equal (this includes infinities); integer and boolean outputs must be equal; shapes and element types must be equal.
- **Status.** `unsupported-op`: no kernel for the operator at that opset, or the operator rejects an attribute value or rank it does not handle. `unsupported-type`: an element type or value kind the library does not have (string, 4-bit, 8-bit float, map; sequences and optionals of tensors are supported). `not-exact`: exact mode only, an operator without an exact kernel. `fail`: anything else that is not a pass.
- **Reading the gaps.** Cases at opset 6 (the legacy pytorch models and a few operator versions) are below the supported range, which starts at opset 7. The rest are listed by cause in the operator table: element types the tensor layer does not have, the `ai.onnx.ml` and training domains, random-number operators and training modes, and the newest preview operators. `known-diff` cases are explained in the runner (`ConformanceRunner.KnownDifferences`) and count as neither pass nor fail.
- **Attribution.** A node case counts under its only operator; a case with several operators (the `_expanded` function bodies) counts under the longest operator name its case name starts with.
